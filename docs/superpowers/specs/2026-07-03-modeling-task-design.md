# 打点建模第一版设计

## 1. 建设目标

新增一套独立的打点建模功能，用于现场通过 RTK 记录区域边界，自动识别子区域和连接段，生成清扫任务路径，并在预览确认后一键执行。

该功能不混用现有多点测试和旧自动清扫链路。第一版新建建模执行调度器，但复用现有底层 RTK 行驶、转向、纠偏、停车和串口控制能力，降低现场联调风险。

## 2. 第一版范围

第一版包含以下能力：

- 模型列表：新建、加载、保存、删除。
- 草稿机制：向导过程中自动保存草稿，正式模型由用户手动保存。
- 区域组管理：打点前必须先选择或创建当前区域组。
- RTK 打点：一个“记录当前点”按钮，后端完成 RTK 均值采样。
- 自动识别：自动识别角点、边界辅助点、连接锚点、子区域、子区域连接段。
- 人工确认：识别置信度不足时，用户必须确认后才能生成和执行任务。
- 区域组连接段：用户选择两个区域组后，只打起点和终点两个点。
- 任务生成：沿用旧任务段字段格式，生成可执行任务路径。
- 路径预览：执行前强制预览并确认。
- 一键执行：通过新的建模执行调度器执行，FSM 使用 `action=modeling_task`。
- 开发者调试：开发者模式补充打点建模调试面板。

第一版不包含以下能力：

- 摄像头建模。
- 曲线区域组连接段。
- 每个子区域单独设置清扫方向。
- 自动区域组排序。
- 通过旧 `config.json` 或旧 `/vehicle/autoDrive` 作为建模任务执行入口。

## 3. 核心概念

### 3.1 模型

模型是一次现场建模结果的完整 JSON 数据，包含区域组、点位、连接段、识别结果、生成任务、预览统计和版本信息。

模型分为两种保存状态：

- 草稿模型：每次打点、识别、排序、连接段修改后自动保存。
- 正式模型：用户点击保存后生成，可被加载、删除和执行。

### 3.2 区域组

区域组是用户主要管理单位。一个区域组可以包含多个子区域和子区域连接段。

现场典型场景是多个看起来相邻的小区域，中间存在较大缝隙，只能通过某条连接段通过。为了减少现场管理成本，用户不直接维护大量小区域，而是维护区域组。

### 3.3 子区域

子区域是算法在区域组内部自动识别出的实际清扫区域。每个子区域至少需要 4 个角点，边界可以包含额外辅助点，用于表达轻微弧度或不规则边。

### 3.4 连接段

连接段分两类：

- 子区域连接段：区域组内部的连接段，由算法根据连接锚点自动识别。
- 区域组连接段：区域组之间的连接段，由用户手动选择两个区域组后打起点和终点。

## 4. 点位模型

每个点都保存两套坐标：

- 相对坐标：用于建模、路径规划、页面展示，单位厘米。
- 绝对坐标：RTK 经纬度，随点保存，用于最终任务执行。

点位来源是机器人当前 RTK 采样结果。点位允许多个角色：

- `corner`：子区域角点。
- `boundary_point`：边界辅助点。
- `connector_anchor`：连接锚点。
- `unknown`：暂不能识别的点。

连接点可以同时是边界点，例如 `roles=["boundary_point", "connector_anchor"]`。

区域内部建议保存三类点集：

- `cornerPoints`：角点。
- `boundary`：完整边界顺序，包含角点、边界辅助点和连接锚点。
- `anchors`：连接锚点。

## 5. RTK 打点采样规则

第一版打点由后端强校验，不使用隐藏默认数据。

采样规则：

- 采样时长：3 秒。
- 有效点数：至少 10 个。
- RTK 固定解：必须为固定解，质量值 `quality=4`。
- GGA 数据年龄：不超过 2 秒。
- 车辆状态：采样期间 FSM 必须非运行，车辆必须静止。
- 离散半径：不超过 5 cm。

采样成功后保存：

- 均值 `lat/lon/heading`。
- 采样点数量。
- 采样开始和结束时间。
- RTK 质量状态。
- 原始采样点摘要。
- 离散半径或估计误差。

采样失败时不保存点，并返回明确失败原因，例如 RTK 未固定、车辆移动、有效点不足、离散过大。

## 6. 自动识别规则

系统不要求用户切换“子区域模式”或“整体轮廓模式”。用户只负责在当前区域组内打点，系统根据点位关系自动识别。

识别目标：

- 子区域边界。
- 子区域角点。
- 边界辅助点。
- 子区域连接锚点。
- 子区域连接段。
- 无法判断的点。

典型场景支持：

- 用户按单个子区域顺序打点，例如 `A1 B1 C1 D1`，再打 `E1 E2` 连接另一个子区域。
- 用户按大区域外轮廓顺时针打点，例如 `A1 B1 E1 E2 A2 B2 C2 D2 C1 D1`。
- 边界存在轻微弧度，用户在边线上追加多个辅助点。

识别结果分三类：

- 高置信度：自动保存并允许进入下一步。
- 中低置信度：保存为待确认，UI 显示原因，要求用户确认点类型或连接关系。
- 无法识别：标记为 `unknown`，允许继续打点和预览，但不允许生成和执行任务。

未确认模型允许继续采集点位，但禁止生成任务、禁止一键执行。

## 7. 清扫路径生成规则

任务顺序分两层：

- 区域组顺序：用户手动排序。
- 区域组内部子区域顺序：默认按连接图路径距离“最远优先”。

清扫方向：

- 区域组统一设置清扫方向。
- 子区域继承区域组清扫方向。
- 默认方向为区域组首条有效边的垂直方向。
- 用户可输入或微调角度。

清扫线计算：

- 滚刷宽度按约 116 cm。
- 边缘尽量外扩覆盖 5-10 cm。
- 相邻清扫线需要重叠。
- 重叠默认至少 10 cm，由系统根据区域宽度自动计算。
- 不设置 20 cm 上限；如果计算出的重叠过大，UI 给出警告。
- 目标是折返后回到该区域入口侧。
- 如果折返次数不能刚好回到入口侧，可以自动重复最后一条清扫线返回。

## 8. 任务格式

第一版生成任务继续沿用旧任务段格式，便于复用底层 RTK 执行能力。

任务段示例：

```json
{
  "id": 1,
  "mode": 1,
  "areaNumber": 1,
  "startX": 0,
  "startY": 0,
  "endX": 120,
  "endY": 0,
  "startLat": 32.03647723,
  "startLon": 118.92449094,
  "endLat": 32.03650874,
  "endLon": 118.92449213,
  "heading": 92.3,
  "length": 120
}
```

字段含义：

- `id`：任务段编号。
- `mode`：任务段类型。
- `areaNumber`：任务区域编号。
- `startX/startY`：任务起点相对坐标，单位厘米。
- `endX/endY`：任务终点相对坐标，单位厘米。
- `startLat/startLon`：任务起点 RTK 经纬度。
- `endLat/endLon`：任务终点 RTK 经纬度。
- `heading`：由起点到终点直线计算出的固定航向角。
- `length`：任务段长度。

## 9. 后端设计

建议新增独立建模模块：

- `modeling_store.py`：本地 JSON 模型读写、草稿读写、模型列表、新建、删除。
- `modeling_sampler.py`：RTK 均值采样、静止检测、RTK 质量检查、采样失败原因。
- `modeling_recognizer.py`：点类型识别、子区域识别、连接段识别、置信度输出。
- `modeling_planner.py`：清扫线生成、区域组顺序拼接、任务段输出。
- `modeling_executor.py`：建模任务执行调度器，复用底层 RTK 行驶、转向、纠偏和停车函数。
- `modeling_routes.py` 或接入 `main.py`：提供前端 API。

后端 API 建议：

- `GET /modeling/models`：模型列表。
- `POST /modeling/models`：新建模型。
- `GET /modeling/models/<id>`：加载模型。
- `POST /modeling/models/<id>/save`：保存正式模型。
- `DELETE /modeling/models/<id>`：删除模型。
- `POST /modeling/draft`：保存草稿。
- `GET /modeling/draft/<id>`：读取草稿。
- `POST /modeling/groups`：创建区域组。
- `POST /modeling/groups/<id>/sample-point`：记录当前点。
- `POST /modeling/recognize`：执行或刷新自动识别。
- `POST /modeling/group-links`：新增区域组连接段。
- `POST /modeling/plan`：生成任务路径和预览统计。
- `POST /modeling/execute`：预览确认后一键执行。
- `POST /modeling/stop`：停止建模任务执行。
- `GET /modeling/status`：读取建模状态。

## 10. 前端设计

工作台新增入口：打点建模。

第一版使用向导式页面：

1. 选择或新建模型。
2. 选择或新建区域组。
3. 记录当前点。
4. 查看自动识别结果。
5. 添加区域组连接段。
6. 任务路径预览。
7. 一键执行。

页面关键要求：

- 打点按钮只有一个：“记录当前点”。
- 采样期间显示采样进度、RTK 状态、静止状态。
- 识别结果必须可视化显示。
- 低置信度点位或连接关系需要人工确认。
- 模型未确认时，生成和执行按钮禁用。
- 执行前必须展示路径预览确认。

开发者模式新增“打点建模调试”面板：

- 当前模型、草稿状态、正式保存状态。
- 当前区域组。
- 最近一次采样原始点摘要、均值点、离散半径、RTK 质量。
- 点位识别结果和置信度。
- 子区域列表和连接段列表。
- 生成任务段数量、总长度、清扫线数量。
- FSM `action`、建模内部阶段、执行段索引、失败原因。

## 11. FSM 和运行状态

建模执行并入统一 FSM：

- 主生命周期仍使用现有 `INITIALIZING / STOPPED / READY / RUNNING / PAUSED / STOPPING / COMPLETE / BLOCKED / FAULT / DISABLED`。
- 建模执行时主状态为 `RUNNING`。
- 当前动作为 `modeling_task`。
- 建模内部阶段写入 runtime detail，不作为独立主 FSM 状态。

建模内部阶段：

- `DRAFTING`：草稿编辑中。
- `SAMPLING_POINT`：RTK 采样中。
- `RECOGNIZING`：模型识别中。
- `PLANNING`：任务路径生成中。
- `WAIT_PREVIEW_CONFIRM`：等待路径预览确认。
- `EXECUTING`：任务执行中。
- `COMPLETE`：建模任务完成。
- `BLOCKED`：建模任务阻塞。

Redis 只作为镜像层和外部读取缓存，不允许 Redis 反向修改 FSM。

## 12. 执行链路

执行链路：

1. 用户完成模型识别确认。
2. 用户生成任务路径。
3. 前端展示路径预览和统计信息。
4. 用户确认后点击一键执行。
5. 后端进入 `modeling_task`。
6. 建模执行调度器按任务段依次调用底层 RTK 行驶、转向、纠偏、停车能力。
7. 每段执行进度写入 runtime detail 和开发者调试状态。
8. 完成后 FSM 进入 `COMPLETE`。
9. 失败或安全条件不满足时 FSM 进入 `BLOCKED`，保留失败原因。

建模任务不写旧 `config.json` 作为执行入口，不通过旧自动清扫接口启动。

## 13. 错误处理

必须阻止保存点的情况：

- RTK 未固定。
- GGA 超时。
- 有效采样点不足。
- 采样期间车辆移动。
- 点位离散半径超过 5 cm。
- FSM 处于运行或停止中等不允许采样的状态。

必须阻止生成任务的情况：

- 当前模型没有区域组。
- 区域组内没有有效子区域。
- 子区域角点不足。
- 存在未确认识别结果。
- 区域组连接关系无法形成可执行路径。

必须阻止执行的情况：

- 未经过路径预览确认。
- 当前 FSM 不允许启动任务。
- RTK 当前不可用。
- 任务路径为空。
- 建模任务已经运行中。

## 14. 测试目标

后端测试：

- RTK 采样成功保存均值点。
- RTK 未固定、车辆移动、离散过大、有效点不足时不保存点。
- 任意打点顺序下可识别子区域和子区域连接段。
- 边界辅助点不会误判为新子区域。
- 中低置信度识别结果阻止任务生成。
- 任务输出字段兼容旧任务段格式。
- 建模执行使用 `action=modeling_task`。
- 停止、完成、阻塞状态正确写入 runtime state。

前端测试：

- 工作台出现打点建模入口。
- 向导步骤按顺序展示。
- 未选择区域组时不能打点。
- 采样中按钮禁用并显示状态。
- 未确认模型不能生成和执行。
- 路径预览确认前不能执行。
- 开发者模式显示建模调试面板。

联调测试：

- 现场静止采样稳定性。
- 子区域连接段识别准确性。
- 区域组连接段执行连通性。
- 清扫线重叠和边缘覆盖效果。
- 一键执行中停止、阻塞、完成状态显示一致。

## 15. 验收标准

第一版验收标准：

- 用户可以从工作台进入打点建模向导。
- 用户可以新建模型、选择区域组、记录当前点。
- 采样失败时 UI 显示明确原因，且不会保存脏数据。
- 系统可以自动识别子区域、边界辅助点和子区域连接段。
- 不确定识别结果必须人工确认。
- 用户可以手动添加区域组连接段。
- 系统可以生成旧任务段格式的路径。
- 执行前必须预览确认。
- 一键执行走建模执行调度器，并在 FSM 中显示 `action=modeling_task`。
- 开发者模式可以查看采样、识别、规划、执行状态。
